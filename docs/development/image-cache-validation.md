# 图片构建与离线验证

验证日期：2026-11-18。基线为 `9666acf`，验证使用 Node.js 24、Sharp 0.35.5 和 Actions 上的 Chrome。记录对应本次 96 项配方、32 项武器手册与 144 张原始图片。

## 图片处理

原图保留在第三方来源目录。生产构建只裁掉完全透明的外边距，按比例缩小，不放大或裁掉可见像素；方图最大边 192 px，横向图片最高 192 px、最宽 256 px。WebP 比较 quality 85 / alpha 100 与无损编码，保留较小结果；未改变画布时还会与原文件大小比较。

图片在 Vite 内容哈希计算前生成，作为独立资源输出，不内联进 JavaScript。采用独立文件便于懒加载、按图片更新及复用缓存，没有合成整站图集。

| 指标                                      |              优化前 |             优化后 |
| ----------------------------------------- | ------------------: | -----------------: |
| 当前 144 张源图片合计                     |         1,354,824 B |          944,896 B |
| 构建中实际独立 WebP                       | 1,189,242 B / 94 个 | 936,058 B / 142 个 |
| 全部 JavaScript 原始体积，不含 SW         |           483,753 B |          285,014 B |
| 全部 JavaScript 分文件 gzip 合计，不含 SW |           226,663 B |           73,138 B |

第一行比较同一批原图与构建副本，图片减少 30.3%。其余行比较旧应用与本次应用；旧版包含 143 张源图，本次新增员工卡并加入 PWA。优化前部分图片内联在 JavaScript 内，不能只比较独立 WebP 文件大小。构建输出数少于源图数，是内容哈希复用了相同字节资源。

首次联网会后台缓存完整应用和图片，因此首次请求总数不会减少。1440 px 首屏又从两列变成三列，会加载更多可见图片。浏览器测量中页面 JavaScript 传输约从 219 KB 降到 65 KB；完整离线资源随后复用缓存。这些是本地 HTTP + 文本 gzip 的资源测量，不代表公网加载时延。

## 行为验证

49 项 Node 测试覆盖资料引用、员工卡成本、排序、用户存储、图片处理和 SW 生命周期；另通过严格类型、Oxlint、Oxfmt 以及根路径 / Pages 子路径构建。

浏览器检查覆盖 1440 / 1024 / 390 / 320 px、三列 / 两列 / 单列、方形物品图与横向枪图、96 项配方和 32 把枪械图片解码、中文名和旧别名、解锁后排序与刷新恢复、员工卡 80 / 6 / 10 材料、手机抽屉及断点切换保留草稿。

在全新浏览器上下文中，只在线访问配方页后断网，直接打开另外三个工具及配方路由，所有页面和图片加载成功，用户存档保持一致。Pages 子路径的双标签更新验证了：新版等待点击；只刷新点击的页面；另一标签页的打印草稿、存档和旧资源继续可用。

`scripts/browser-smoke.mjs` 需要额外可用的 Playwright 与 Chromium；它们只用于验证，不进入应用依赖。脚本支持 `DMZ_PLAYWRIGHT_MODULE`、`DMZ_CHROMIUM_EXECUTABLE`、`DMZ_SMOKE_DIST`、`DMZ_SMOKE_BASE` 和可选 `DMZ_SMOKE_NEXT_DIST`。截图输出在忽略提交的 `.qa/`。中文布局验证机应安装可用的中文字体。
