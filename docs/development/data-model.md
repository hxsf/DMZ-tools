# 数据模型

本轮先收集 2026 年《现代战争4》DMZ 首发期资料样本，再设计类型。样本用于验证数据能否准确表达，不是完整物品库，也没有宣称当前版本游戏实测。收集日期为 2026-11-05，具体出处见 `src/data/sources.ts` 和 [来源登记](../external/mw4-dmz/ATTRIBUTION.md)。

打印配方先覆盖 10 个代表性记录；武器手册按所查社区收藏目录收录 32 种，对应武器与手册分别作为物品记录。该数量表示本次来源目录的覆盖，不作为跨版本游戏总量的承诺。缺少获取条件不会阻止收录或用户手动标记。

## 类型职责

| 文件                       | 内容                                 |
| -------------------------- | ------------------------------------ |
| `src/types/source.ts`      | 来源、事实声明和冲突声明             |
| `src/types/item.ts`        | 物品 ID、名称、分类、材料数量        |
| `src/types/recipe.ts`      | 打印配方、成本、产出与打印前置       |
| `src/types/unlock.ts`      | 解锁条件、打印能力和武器手册解锁规则 |
| `src/types/catalog.ts`     | 一批资料及其版本、覆盖范围           |
| `src/types/progress.ts`    | 用户库存、解锁记录、存档版本         |
| `src/types/requirement.ts` | 搜集或制作目标、计划状态与优先级     |

类型文件只定义契约，不引入 Preact 或 Signals。静态资料通过 `satisfies` 接受类型检查；跨记录引用、非负整数等约束仍需运行时检查。用户存档与资料版本分别演进，不把资料复制进每个存档。

## 事实与未知

成本、产量、解锁方式按字段记录 `Fact<T>`，不能用一条总体“已验证”标记覆盖不同质量的信息：

- `reported`：所引来源有记载，附来源 ID；不等于游戏实测。
- `unknown`：尚未找到足够证据，不提供猜测值。
- `conflicting`：保留至少两项有出处的说法，不自动选一个用于计算。

样本中“防辐射药”的材料成本存在社区来源分歧，以冲突形式保存。网页中的 `+1` 可能只是加入清单按钮，当前未确认每次打印的产出数量，因此保持未知。未记载的现金成本用 `null` 表示；只有明确确认无现金费用才填 `0`。

后续计算器按“目标成品数量”工作，需要先确定每次产量。遇到未知或冲突应返回待确认信息，不能静默按一次一个、免费或其中某个成本继续计算。用户手动采用的临时值应与来源事实分开保存。

## 物品、配方与解锁

`Item` 区分基础资源、实体材料、装备、武器和武器手册。基础资源与材料共用 `ItemAmount`，中间材料作为配方产出仍引用同一个物品 ID。名称保留英文和中文来源类别，中文别名仅用于搜索；ID 使用本项目的稳定键，不冒充官方编号。

简体中文是首版面向用户的语言。游戏名称随物品资料保存，界面按钮、状态和提示使用独立的翻译文案。名称缺少中文时回退英文，检索同时考虑中英文与别名。`zhCNOrigin: "official"` 表示官方发表过该名称，具体出处见物品 `sourceIds`，不表示已核对游戏客户端。官网自身存在译名差异，详见 [名称核对记录](../../src/data/README.md#中文名称核对)。更换译名或界面语言不改变稳定 ID 和用户进度。

`Recipe` 表示一项打印定义，分别保存：

1. `output`：打印出的物品和每次产量。
2. `cost`：物品消耗及现金消耗。
3. `unlock`：获得配方的条件，支持等级、任务、搜到后撤离、能力解锁以及 AND/OR 组合。
4. `requires`：制作所需的打印机和打印能力。

获得等级奖励中的一个成品，不代表解锁了其配方；配方已解锁也不代表打印类别或材料制作升级已完成。能力单独记录，例如普通打印机、战场升级打印类别、精制材料打印和史诗材料打印。当前只列出样本涉及的能力，后续按证据增加。

手册物品关联对应武器；`WeaponManualUnlock` 可补充已知的获取机制，但不要求先收集完整条件才能收录手册。配方的 `unlock` 同样是可选资料。手册与配方均由用户手动确认是否解锁，获取条件不限制勾选。通用手册机制、单个手册售价和撤离奖励不是同一事实，不用通则强行填满每条记录。武器外观蓝图和重复手册带来的迷彩进度不在本轮范围。

## 用户记录

`Inventory` 仅记录用户确认的仓库数量。不存在的键表示尚未录入，显式 `0` 才表示确认没有；局内尚未撤出的搜集物不直接写进仓库。

`UnlockProgress` 分开保存配方、手册和能力的确认状态。没有记录等价于未知，不能按等级自动标成已解锁。确认记录带时间，玩家等级单独保存。

`RequirementPlan` 包含标题、优先级、启用/暂停/完成状态和目标。目标可为搜集物品或制作成品；不同目标的相同材料汇总后共用库存，不能各自重复抵扣。编辑或完成计划不会自动扣除库存，实际制作操作将单独实现。

用户存档只保存基础记录，不存 Signals 对象、缺口或完成率。公共 store 使用工厂创建，便于测试和隔离；存储提供显式异步读写操作，暂不自动订阅或接入页面。`loadSnapshot(kv)` 和 `saveSnapshot(kv, snapshot)` 依赖通用 `AsyncKV`，浏览器实现由 `createBrowserKV()` 提供。存档键 `dmz-tools:user`、版本 1 和 JSON 格式保持不变，可直接读取现有 localStorage 数据。

调用方必须等待加载完成，区分有效存档、没有存档、无效内容、不支持的版本与访问失败。只有有效恢复或确认键不存在后才可进入正常保存流程，读取失败不能被默认空值覆盖。保存会在等待 I/O 前校验并序列化快照，写入成功后才返回 `saved`；无效快照不触发写入。调用方应等待一次保存完成后再发起下一次，未来自动保存也要串行化，避免较旧的远端写入晚到而覆盖新记录。远端认证、离线同步及多端冲突处理待具体实现时设计。

KV 读写通过 `ts-results-es` 返回 `Result`，加载与保存函数显式处理 `Err`，保留底层 `KVError` 至结果的 `error` 字段。序列化失败单独使用 `invalid-snapshot` 错误码，不与存储访问错误混淆。原始 `cause` 仅用于诊断，不进入用户存档。存档层仍使用 `ready`、`empty`、`unsupported-version` 等有业务含义的状态，避免调用方丢失版本与内容错误的区别。
